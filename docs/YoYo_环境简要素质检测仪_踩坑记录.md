## 1. Keil C51 工具链与中文编码

### 1.1 ★ 编译器吞掉 GBK 源码中的 `0xFD` 字节（最隐蔽）
**现象**：源码中的中文字符串完全正确，字库地址公式也正确，但 OLED 上个别字显示成别的字（如 `正常` 显示为 `粘`）。

**定位**：把要显示的字符串按十六进制打到串口，与源码字节对账，发现运行时字符串比源码少了 `0xFD` 一个字节。
- `正常` 的 GBK 是 `D5 FD B3 A3`，编译后变成 `D5 B3 A3`；丢 `FD` 后 `D5 B3` 恰好是「粘」。
- 反例：`在线` 的 GBK 是 `D4 DA CF DF`（不含 `FD`），显示正常。

**结论**：**Keil C51 在读取 GBK 源码时，会丢弃含有 `0xFD` 的字节。** 凡 GBK 码里含 `FD` 的汉字（`正`=D5FD、`数`=CAFD、`三`=C8FD …）都会受影响。

**规避**：把源码中「前导字节 + `0xFD`」的组合改写成 C 转义：`\x<前导>` + `\375`（用八进制避免 `\xFD` 与后续十六进制字符连读）。可用脚本对源文件做一次批量处理。更稳妥的写法是字符串中所有 ≥0x80 的字节都写成 `\xNN`。

### 1.2 编辑器/命令行
- **UV4 命令行编译**：UV4 是 GUI 程序，必须 `Start-Process ... -Wait`，否则拿不到退出码：
  ```powershell
  Start-Process "C:\Keil_v5\UV4\UV4.exe" -ArgumentList '-b',<uvproj>,'-o',<log> -Wait
  ```
  退出码 0/1 = 成功（1 表示有警告），≥2 = 错误。
- **L16 warning**（UNCALLED SEGMENT）通常无害，但若出现说明某些函数确实未被调用。

### 1.3 内存模型与 DATA
- 工程原为 **small 模型**（`data` 段仅 **128 字节**），2026-10 引入 FatFs 后已切到 **large 模型**（`<MemoryModel>2</MemoryModel>`，变量进 xdata）。**>8 字节的缓冲区一律放 `xdata`**；编译后请关注 `Program Size` 的 `data=` 值，逼近 128 会链接失败（Target not created）。
- **`const` 数组/表默认进 DATA** —— 必须写成 `static const unsigned char code ...[]`，否则白占 DATA。
- **8051 链接器不会为"未被调用"的函数做 DATA 覆盖复用** —— 想省 DATA 应用"自检调用"（让链接器认为被调用），而不是 `#if 0`。

### 1.4 中文源码编辑（GBK）
- 源码为 **GBK 编码**。用文本/脚本编辑时正确姿势（PowerShell）：
  ```powershell
  $gbk=[Text.Encoding]::GetEncoding(936)
  $t=$gbk.GetString([IO.File]::ReadAllBytes($f)); ... ; [IO.File]::WriteAllText($f,$t,$gbk)
  ```
- **坑**：用脚本/正则批量删除或替换 `.c` 里的函数时，很容易**误伤相邻代码**（跨行匹配尤为危险）。改完务必核对函数列表/行数并重新编译——安全做法是**改前留副本**。
- **坑**：PowerShell 单引号字符串不解析 `` `n ``；插入多行文本要用双引号或 here-string，否则会把字面量反引号写进源码。

## 2. 电源与 ADC

### 2.1 USB 直供 5 V 绕过电源开关
USB VBUS 经 D3 直供 `VCC_5V`，插着 USB 时 MCU 一直有电，**无法冷启动下载**。解决：加 **3.3 V 断电跳线 H1**。

### 2.2 12 V 指示灯微亮 / 电池 ADC 被污染
USB 供电时降压芯片内部上管体二极管把 5 V 反灌到 12 V 轨（抬到 ~4.5 V）。解决：串入 **防反二极管 D1(SS54)**。

### 2.3 ADC 电池采样
- **对齐方式**：12 位结果左对齐时，低 4 位在 `ADC_RESL` 的高 4 位（低 4 位恒 0）。旧代码写 `ADC_RESL & 0x0F` 取到的永远是 0 → 结果被砍成 16 的整数倍。正确：`((unsigned int)ADC_RES << 4) | (ADC_RESL >> 4)`。
- **单次噪声大**：单次采样散布 ±180 LSB，但 **16 次平均后稳定在 12.0~12.1 V**。电压本身是稳的，是采样链噪声。**软件必须做平均**。
- 排查表明噪声与采样时间无关；读内部 1.19 V 基准通道（ADC15）也在散 → 指向 **ADC_VRef+（CJ431）去耦/稳定性**。下一版建议：CJ431 并 1 µF + 0.1 µF；P0.1 到 GND 加 1~10 nF。
- 实测 `ADC_VRef+ ≈ 2464 mV`（标称 2500 mV）。

## 3. 共享 SPI 总线（BMP581 / TF / OLED / 字库）

四从机共用 `MOSI=P1.3, MISO=P1.4, SCK=P1.5`，各自 CS 见设计说明。

### 3.1 MISO 无上拉（共性根因）
`MISO(P1.4)` **没有上拉**，空闲时悬空（实测 0/1 乱跳）。任一从机被误选中/虚焊，就会抢 MISO，把别的器件一起拖死。**建议飞线到 3.3 V 加 10k 上拉。**

### 3.2 BMP581
- **读寄存器不需要 dummy 字节**（手册 5.5.3）。多加 dummy 会导致读数整体错位一个地址，表现为"阶梯状乱码"。
- **寄存器地址**：`0x00` 保留（读回 0x00）、`0x01` = **CHIP_ID = 0x50**、`0x02` = **REV_ID = 0x32**。曾误记 CHIP_ID 在 0x00。
- 数据寄存器 TEMP=`0x1D/1E/1F`、PRESS=`0x20/21/22`；CMD 字节 = `bit7=R/W(读=1) | bit6:0=地址`。
- **气压读不到（恒 `7F 7F 7F`）**：`7F7F7F` 是 BMP581 的"该通道无数据"标志。根因是**开机第一次写配置寄存器（OSR_CONFIG `0x36` 的 press_en、DSP `0x30`）时没写进去**（`g_bmp_cfg_done` 一次标志把失败固化，之后再不重写）→ 气压通道一直没使能。改成**每次读都重写一遍配置**后正常。诊断方法：回读 `0x36` 应得 `0x50`（press_en=1）。
- 支持 mode 0 / mode 3，数据在 SCK 上升沿锁存。温度=raw/65536 ℃、压力=raw/64 Pa（24 位有符号）；片内 DSP 补偿（`0x30 DSP_CONFIG.comp_pt_en=0b11`）。

### 3.3 TF / SD 卡
- **SPI 时钟档位（最致命）**：STC8H `SPCTL.SPR` 中，**SPR=3 档在本板会读出规律性错位** `FF FE FD FB F7 EF DF BF`（每 7 bit 一个 0）——不是卡的问题。正确做法：**初始化用 SPR=2（最慢），传输切 SPR=0**。
  - 实测（24 MHz，2000 字节）：SPR=0 → 6 ms，SPR=1 → 8 ms，SPR=2 → 13 ms，SPR=3 → 3 ms（最快，SD 卡用不了）。
    - ※ STC8H 手册（§23.2.2）：`SPR[1:0]=11` 在**快速 SPI** 下为 `SYSclk/2`（其余档 /4、/8、/16），故 SPR=3 反而最快 —— 不是笔误。
  - 注意 SPR=3 对 BMP581 可用（支持 10 MHz），只是对 SD 太快。
- **卡检测极性**：实测**插卡 `TF_CD(P0.4)=0`，不插卡=1**。旧代码判断相反。
- **SDSC 与 SDHC 寻址不同**：≤2 GB 为 SDSC 用字节地址（lba×512，须先 CMD16 设块长 512）；≥4 GB 用块地址。由 CMD58 的 OCR.CCS 位与 CSD 判断。
- 初始化序列：`CMD0 → CMD8 → CMD55+ACMD41(HCS=1) → CMD58 → CMD9 → CMD10 → CMD16 → CMD17`。

### 3.4 OLED（SSD1306 128×64）
- 一行最多 **8 个汉字**（128 px ÷ 16 px）。字符串过长时，若从 `col≥120` 起画 16 宽的汉字，页模式列地址会 128→0 **回卷覆盖行首** → 行首显示乱字。**画之前需判断放得下**。
- 旋转 180°：初始化 `0xA0`（段重映射）+ `0xC0`（COM 扫描）一起设置。
- 数据类型坑：湿度曾用 `unsigned char` 存放 ×10 的值（0~1000）→ **超过 25.5% 回绕**；海拔用 `int` 却按无符号打印 → 负高度变 65516。应使用正确宽度与带符号输出。

### 3.5 中文字库 GT20L16S1Y
- **必须用位翻转 SPI，且在 SCLK 拉低时采样 MISO**。硬件 SPI（尤其 SPR=3）会读阶梯状乱码 `0x00 01 03 07 0F…`（与 §3.3 的 SPR 问题疑为同源，可先试 SPR=0）。
- 地址：15×16 汉字 `((区−0xB0)*94 + (位−0xA1) + 846)*32`；8×16 ASCII `(c−0x20)*16 + 0x3B7C0`；命令 `0x03` + 24 位地址。

## 4. I²C 传感器

### 4.1 SHT45
换算公式的偏移不可漏：`T = −45 + 175·t/65535`、`RH = −6 + 125·rh/65535`。漏偏移会使温度虚高 45 ℃。建议加 CRC8 校验（poly 0x31，init 0xFF）。

### 4.2 VEML7700（上电默认关闭）
寄存器 `ALS_CONF(0x00)` 上电默认 = `0x0001`（`ALS_SD=1` 关闭），不配置则 ALS 恒读 0。需先写 `0x0000` 开测并等一个积分周期。**ALS 是一个 16 位寄存器**（对 `0x04` 连续读 2 字节，`0x05` 是 WHITE）。

### 4.3 SCD41（已损坏）
- **必须先 `start_periodic_measurement(0x21B1)`**，信号 5 s 更新一次；设置类命令必须在 idle（先 `0x3F86` stop）。
- **顶面白色 PTFE 保护膜不可撕除**（手册 4.1/4.5 两处 "must not be removed"）——它同时是声学腔体边界，撕后 CO₂ 通道永久失效。损坏证据：CO₂ 恒 0 而 T/RH 正常；idle 下自检 `0x00C4`（MALFUNCTION）；呼气 RH 变化而 CO₂ 不动；factory reset 无效。
- 焊接：`>220 ℃` 时间 `<60 s`、峰值 `≤235 ℃`、焊后禁水洗；MSL3 拆袋 168 h 内用完。

### 4.4 IST8310（地址 0x0C）
上电为 **Stand-By**，数据寄存器恒 0：每次读前写 `CNTL1(0x0A)=0x01` 触发单次测量，等 ≥6 ms 再读 `0x03~0x08`（每轴低字节在前）。手册推荐 `AVGCNTL(0x41)=0x24`、`PDCNTL(0x42)=0xC0`。WHO_AM_I(0x00)=0x10。

### 4.5 GPS 授时 / PCF8563
- GPS 默认 115200；**须先定位成功**。判断有效定位最可靠的是 `$GxRMC` 字段 2 = `A`；统计可见卫星数要按星座累加。
- PCF8563 写时间寄存器 `0x02~0x08`（BCD），`0x02` bit7 为 VL 标志（无备电时置 1，写 0 清除）。**板载 RTC（PCF8563）本身无备电**，靠 GPS 授时；**GNSS 模块有备电**（CN2，1.25-2P，见设计说明 §8），用于保 RTC/星历、加快定位。建议开机授时一次。

## 5. RS485 / Modbus

### 5.1 从机地址必须唯一（最常误判）
一条总线一个主站，**同一地址的从机不能同时挂**。本项目噪声/风速/风向/（旧噪声模块）出厂默认都是地址 1，一起挂就会同时应答、撞帧，主站收到乱码。必须先改成 1 / 2 / 3。

### 5.2 无应答时的排查顺序
1. 依次试 **9600 / 4800 / 2400** 与地址扫描（1~247）；
2. **A/B 对调**（不同厂家 A/B 定义可能相反）；
3. 传感器端**确有供电**（如 12 V）且**与主板共地**；
4. 确认是 **RS485 版**（不是 4-20 mA / 0-10 V / 脉冲版，那些无 Modbus）；
5. 终端/偏置（板上有 120 Ω，传感器若自带就别叠太多）。

### 5.3 阻塞主循环导致按键失灵
Modbus 读在无应答时会等满超时（3 次 × 200 ms ≈ 600 ms），主循环被卡住 → 按键扫描漏采、短按失灵。解决：**超时降到 50 ms**，并在**等待应答的空转里也调用按键扫描**。

### 5.4 寄存器与改参数
| 设备 | 地址 | 寄存器 |
|---|---|---|
| 噪声 | 1 | `0x0000` = 瞬时噪声 ×0.1 dB |
| 风速 | 2 | `0x0000` = 风速 ×0.1 m/s、`0x0001` = 风级 |
| 风向 | 3 | `0x0000` = 角度 ×10、`0x0001` = 整数角度 |

改地址（广播）：`FF 06 07 D0 00 <新地址> <CRC>`；改波特率（**噪声/风速/风向通用**）：`<当前地址或FF> 06 07 D1 00 <0/1/2> <CRC>`（实测风向也支持 0x07D1）。

## 6. 硬件设计（第一版评审）

第一版评审发现并修正（第二版）：
1. **CH340N 的 RXD/TXD 接反**（废板）。
2. **LDO1 ME6211 符号 pin2/pin3 对调**（2=VSS→GND、3=CE→VCC），原 LDO 使能脚接地 → 常关断。
3. **PMS7003 排母 U10 引脚重排**为 `1/2=VCC、3/4=GND、5=RESET、7=RX、9=TX、10=SET`（原排法会 5 V 对地短路 + 模块被复位）。
4. RS485 加 120 Ω 终端 + 510 Ω 失效偏置 + 10k 下拉。
5. GPS 的 ON/OFF、nRESET 加上拉，VBAT 加去耦。
6. 电池分压上端从 VCC_BAT 改到 VCC_CHARGE。
7. IST8310 电源加 4.7 µF；VEML7700 供电加 R30=10Ω + 电容 + 钽。
8. 位号整体重排（U3=CH340N、U4=CJ431 原为反）。

> 教训：**PCB 下单前必须逐脚对数据手册复核**（脚序、连接器引脚定义），错一条即废板。

## 7. 方法论（可复用）

1. **隔离工程**：一个外设一个最小工程，其余全部拉高/移除，先排除干扰再合并。
2. **字节级对账**：把内部状态/字符串按十六进制打到串口，与源码/手册逐字节比较。
3. **对照实验**：一次只改一个变量（插卡/不插卡、mode0/mode3、SPR 各档、A/B 对调）。
4. **以实测为准**：本项目中 CH340 脚序、IST8310 地址、BMP581 寄存器、ADC 公式均出现过文档与实测不符，应以实测回填文档。
5. **先怀疑共性**：多个同类设备同时异常，优先查它们共同的连接/供电/地址，而非逐个怀疑。

## 8. 补充经验（2026-10）

- **GPS 必须用中断收**：原先 `bsp_gps_poll()` 靠"主循环每圈轮询 UART2"，但主循环一圈 10~150 ms，而 NMEA 是 115200（一句 0.6 ms 就发完），UART2 只有 1 字节缓冲 → **句子几乎全被丢掉，表现为"搜不到星"**（其实模块在正常工作）。改为 **UART2 接收中断 + 环形缓冲**后恢复正常（与 UART3/PMS 同法）。
- **FatFs 在 Keil C51 上需要 large 内存模型**：FatFs R0.16 的静态数据超过 8051 的 128 字节 DATA，报 `DATA: SEGMENT TOO LARGE`。把工程内存模型切到 **large**（`<MemoryModel>2</MemoryModel>`，变量进 xdata）后即可编译（实测 `code≈51 KB / xdata≈2.8 KB / data≈9 B`）。另设 `FF_FS_MINIMIZE=1` 去掉目录类函数，绕开 `f_rename` 局部变量过大的问题；`diskio.h` 需自带 `#include "ff.h"`。
- **中文源码编码转换有一坑**：对 **GBK** 文件"加 UTF-8 BOM → 编辑器改 → 转回"，若中途某步按 UTF-8 解码了 GBK 内容，会出现 `EF BF BD`(U+FFFD) 把汉字吃掉、**不可逆**。安全做法：改动尽量只用 **ASCII 锚点 + PowerShell(GBK) 直接替换**；需要新增中文时写成 `\xNN` 转义字面量，让源码保持纯 ASCII。
- **共享 SPI 的设备切换**：TF（初始化用慢档、传输用快档）、BMP581、OLED、字库共用总线；任何"读乱"先查 SPR 档位与 MISO 抢线。
- **TF 挂载失败 `FR_NO_FILESYSTEM`(0D) 的真因 —— `spi.c` 的 `sd_rb[8]` 越界**：`TF_INIT` 用 `TF_READ_REG16(0x09, sd_rb)` 往 `sd_rb` 读 **16 字节 CSD**，但 `sd_rb` 只有 **8 字节** → 越界 8 字节，把紧邻的全局量 `g_tf_sdhc`（SDSC/SDHC 寻址标志）覆盖成 CSD 里的字节（实测打印出 `0x76`）→ 寻址模式错 → 读分区引导扇区失败 → `mount=0D`。修法：`sd_rb[16]`。**教训：凡"定长读"先核对缓冲大小。**
- **（诊断手法）**：把挂载失败路径做成"读 MBR → 解析分区表 → 读它指向的分区引导扇区"，逐层打印。本次正是靠打印 MBR 里**分区类型 `0C` / 起始 LBA / 大小**，确定卡与扇区读都正常，只剩"非 0 扇区读不了" → 锁定 `g_tf_sdhc` 被写坏。
- **状态灯语义**（P1.6=TF / P1.7=GPS，双色：拉低=绿、拉高=红、高阻=灭）：TF = 记录中绿灯 1 Hz 闪 / 没卡红灯常亮；GPS = 天线断开(OPEN/SHORT)红常亮 / 有天线没星红闪 / 搜星中绿闪 / 稳定定位绿常亮。
- **GPS 页显示最近城市**：内置 `BSP/city_table.h`（341 个地级市，经纬度×100 + 名称，纯 ASCII `\xNN`），按经纬度找最近城市（经度按 cos 加权），画在 GPS 页第 0 行右侧（最多 5 字，`OLED_SHOW_STR` 自带 `col>112` 截断）。数据源：GitHub `88250/city-geo` 的 `data.json`。
- **`\xNN` 转义的贪婪坑**：批量把中文转成 `\xNN` 时，若某转义后紧跟十六进制字符会被 C 贪婪连读（`\x71`+`2` → `\x712` 溢出）→ 编译报 `unterminated string`。安全写法：源码保持原位、只对"含 0xFD 的字"改转义（`\x<前导>` + 八进制 `\375`），或让转义后跟非十六进制字符。
